# NOVA ARQUITETURA DE RISCO

Estamos desenvolvendo uma arquitetura baseada em **dois componentes principais de risco**.

## 1. RISCO CLIMÁTICO

Teremos um modelo relacionado ao risco climático.

O objetivo será produzir algo semelhante a:

`risco_climatico = 0 a 100`

ou:

`probabilidade_risco_climatico = 0 a 1`

Esse componente deverá representar condições ambientais que possam aumentar a possibilidade de ocorrência de um sinistro.

Exemplos de fatores climáticos que poderão ser utilizados conforme os dados disponíveis:

* chuva;
* chuva intensa;
* precipitação acumulada;
* vento;
* temperaturas extremas;
* tempestades;
* condições meteorológicas adversas.

IMPORTANTE:

Não crie dados que não existam.

O modelo deve utilizar somente variáveis realmente disponíveis nas bases que serão utilizadas.

---

# 2. RISCO OPERACIONAL / SINISTRO DE MÁQUINA

Teremos outro modelo relacionado ao risco operacional das máquinas agrícolas.

Esse modelo será baseado principalmente no histórico de sinistros disponível nas bases da SUSEP.

O objetivo será produzir algo semelhante a:

`risco_operacional = 0 a 100`

ou:

`probabilidade_risco_operacional = 0 a 1`

Ele deverá considerar riscos relacionados a eventos como, quando disponíveis nos dados:

* colisão;
* abalroamento;
* capotagem;
* queda acidental;
* danos elétricos;
* incêndio;
* furto;
* roubo;
* impacto;
* acidentes;
* outras causas operacionalmente relacionadas à máquina.

Não assuma que conseguiremos prever mecanicamente uma falha específica da máquina.

Estamos trabalhando com **probabilidade/risco baseado em dados históricos**, não com manutenção preditiva completa.

# CAMADA DE COMBINAÇÃO DOS RISCOS

Os dois componentes deverão gerar scores independentes.

Exemplo:

`Risco Climático = 72%`

`Risco Operacional = 45%`

Depois deverá existir uma camada simples responsável pela combinação desses resultados.

Exemplo conceitual:

`Score Final = (Risco Climático × Peso Climático) + (Risco Operacional × Peso Operacional)`

Os pesos serão definidos pela **Sompo**.

Exemplo:

Sompo seleciona:

`Clima = 70%`

`Operacional = 30%`

Então:

`Score Final = Risco Climático × 0.70 + Risco Operacional × 0.30`

Outro cenário:

`Clima = 30%`

`Operacional = 70%`

Nesse caso, o sistema deverá dar maior importância aos fatores operacionais.

---

# REGRA FUNDAMENTAL

Os pesos devem totalizar:

**100%**

Portanto:

`Peso Climático + Peso Operacional = 100%`

A interface precisa impedir ou corrigir configurações inválidas.

Para o MVP, prefira uma solução extremamente simples.

Por exemplo:

* slider de Clima;
* automaticamente o peso Operacional vira `100 - Clima`;

OU

* dois campos percentuais;
* validação impedindo salvar enquanto a soma for diferente de 100%.

Avalie qual solução apresenta menor complexidade e melhor UX.

---

A alteração dos pesos pela Sompo **NÃO deve retreinar os modelos de Machine Learning**.

Os modelos produzem seus scores independentemente.

A configuração da Sompo apenas altera a **combinação final dos scores**.

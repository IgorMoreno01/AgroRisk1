### Arquitetura desejada

Crie uma camada de adaptadores, mantendo cada API isolada:

* ClimateAdapter
* WaterGeoAdapter
* RoutingAdapter
* TerrainAdapter

Os componentes da aplicação não devem chamar diretamente as APIs externas. O fluxo deve ser:

Frontend → API/backend → Adapter → API externa → normalização → Risk Engine → Frontend

Se o projeto atualmente não possuir backend, avalie a melhor forma de criar uma camada backend/API sem destruir a arquitetura atual.

### Open-Meteo

Comece implementando esta API primeiro.

Ela deve receber latitude e longitude e retornar dados normalizados para o sistema, incluindo quando disponíveis:

* temperatura;
* precipitação;
* umidade relativa;
* velocidade/direção do vento;
* previsão horária.

Crie um endpoint interno para o frontend consumir esses dados.

Não coloque chaves de API ou segredos no frontend.

### Overpass / OpenStreetMap

Depois implemente a consulta de objetos hidrográficos próximos à coordenada:

* rios;
* córregos;
* lagos;
* reservatórios;
* represas;
* canais.

Retorne os dados em um formato interno simples e permita calcular a distância até o equipamento.

### openrouteservice

Depois implemente:

* rota origem → destino;
* distância;
* duração;
* rota alternativa quando disponível.

A API key deve ficar exclusivamente em variável de ambiente/secret do Replit.

Não exponha a chave no frontend.

### OpenTopography

Depois implemente consulta de elevação por coordenada.

A API key também deve ficar exclusivamente em variável de ambiente/secret.

### Requisitos importantes

* usar variáveis de ambiente para todas as chaves;
* timeout nas chamadas externas;
* tratamento de erros;
* retry controlado quando fizer sentido;
* fallback para os dados simulados atuais caso uma API esteja indisponível;
* cache para evitar chamadas desnecessárias;
* logs úteis para debugging;
* não fazer chamadas externas a cada renderização do React;
* manter os dados normalizados em um formato interno único;
* manter o dashboard atual funcionando;
* não substituir os dados simulados até que cada integração seja testada.
